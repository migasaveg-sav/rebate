Archivo de Collections (cobranza)

Se usa para calcular el estatus de pago por SO. Nota sobre el cruce abajo.

El cruce funciona en dos pasos: 1) si la fila trae número de SO en "Body Summary", el cobro se asigna directo a esa SO (match exacto, el más confiable); 2) para las filas sin ese dato, se agrupan por cliente y se reparten (FIFO, de la SO más antigua a la más reciente) contra el saldo pendiente de sus SO incluidas. Rebate extra sobre SO pagadas al 100%

Además del rebate normal (arriba), se calcula un rebate adicional aplicando un % directo sobre el monto de cada SO con líneas RAC/LCAC que se haya cobrado al 100%. No tiene monto mínimo ni requiere que la SO esté libre de descuentos — la única condición es el cobro completo. Este rebate NO se acumula entre periodos: es solo sobre lo cobrado al 100% dentro de cada periodo. El % puede cambiar de un periodo a otro (ej. 2% en junio, 1% en julio) — se define por periodo en el paso 1, junto a cada mes. El valor de aquí es solo el % por defecto que se sugiere para periodos nuevos que aún no tengan uno propio.

Rebate normal (tipo 1) por cliente — acumulado

El rebate se calcula una sola vez por cliente, aplicando los tramos al monto acumulado (periodos anteriores + este periodo) de SO validadas como "Procede", pagadas al 100% y sin descuentos. El importe por SO en las tablas de abajo es el reparto proporcional de este total.

Rebate extra (tipo 2) por cliente — solo este periodo

Directo sobre las SO con líneas RAC/LCAC pagadas al 100% este periodo. Sin mínimo, sin requisito de validación ni de estar libres de descuentos. No se acumula entre periodos.

Rebate por sucursal y cliente

Suma del rebate normal + extra, agrupada por sucursal (Branch), con el subtotal de cada cliente dentro de su sucursal.
